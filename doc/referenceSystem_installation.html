Installation and Distribution

The toolbox ships as a zip archive or a git repository. There is no packaged installer and no .mltbx: nothing stands between the repository and the user, so everything that has to happen before the toolbox works happens in one command.

Install

>> cd <wherever you unpacked or cloned it>/referenceSystem
>> setupReferenceSystem

That is the whole procedure. On a fresh copy it takes about a minute, because it compiles the gateway; afterwards it takes milliseconds.

setupReferenceSystem is the installer, and it is idempotent. Every step compares its inputs against its output and does nothing when the output is already newer, so it is safe to call from startup.m. It does five things:

  1. puts the distribution folder on the path — never +referenceSystem, which is a namespace folder and must not be on the path;
  2. removes any stale or misconfigured entry belonging to this toolbox, including another installation of it;
  3. compiles the MEX gateway if it is missing or if any C source is newer than the binary;
  4. regenerates the function reference if any help block is newer than the page, and rebuilds the Help browser search database if any page is newer than the database;
  5. saves the path, so the toolbox is still there after a restart;
  6. downloads both Earth orientation series and the full SPICE kernel set into data/, skipping anything already present;
  7. prints what it found and what it did.

The defaults install rather than inspect. A first run costs a few minutes and about 700 MB, of which 650 MB is the small-body kernel sb441-n16.bsp; later runs cost milliseconds and no network at all, because every file already on disk is skipped. A failed download never stops setup — the reasons come back in status.fetch.failures and in the summary. Every one of these behaviours is one named argument away from off.

CallUse it when
setupReferenceSystem Normal use. Installs, fetches and saves; builds and downloads only what is out of date or absent.
setupReferenceSystem(Fetch="none") No network, or you do not want the data. Nothing is downloaded.
setupReferenceSystem(KernelSet="minimal") You want the planetary ephemeris de440s.bsp (~31 MB) and not the orientation or small-body kernels.
setupReferenceSystem(Save=false) You want the path for this session only, leaving pathdef.m untouched.
setupReferenceSystem(Verbose=false) A scripted call that should print nothing.
setupReferenceSystem(Build="always") After changing a compiler, a MATLAB release, or anything under mex/ that the timestamp check might not catch.
setupReferenceSystem(Build="never") A read-only installation, a diagnostic run, or a CI job that builds separately. Setup then only reports.

A build failure never stops setup. The path is the one thing setup absolutely has to get right, and a toolbox on the path with no gateway still gives you a working namespace, readable help, and an error that names the missing piece. You get a warning saying what failed and how to see the compiler output in full:

>> referenceSystem.buildMex           % the gateway, with the compiler output
>> referenceSystem.buildDocumentation % the reference page and search database
>> referenceSystem.runTestSuite       % writes referenceSystem_testReport.txt

Those three are every build step the toolbox has.

Distributing by git

Clone, then run setup. The repository holds sources only; every artefact is built locally and is listed in .gitignore:

Not trackedWhy
+referenceSystem/private/mexGateway.mex* The MEX binary is platform-specific, so a committed one is wrong for most people who clone. Worse, it is wrong silently on the platform it was built for once the C sources move on.
doc/helpsearch*/ A database whose format changes between MATLAB releases.
referenceSystem_testReport.txt The report is a deliverable of a run, not of the repository. Committing one invites reading a stale result as a current one.
data/*.txt, data/*.dat Earth orientation and leap-second files are measured data the IERS reissues. Pin a copy deliberately when a result has to be reproducible, and say so.

The stale-binary case is the one that bites, and setup checks for it. Pulling a branch that touched mex/ leaves a compiled gateway older than its own sources. A missing binary announces itself — every call fails. A stale one does not: it runs, it returns numbers, and you are executing one version of the algorithm from MATLAB and another from C. Setup compares the newest C source against the binary and rebuilds when the sources are newer, which only works because the binary is untracked and local.

The generated function reference is committed, deliberately: it is the one artefact a reader may want to open straight from a web view of the repository without a MATLAB session. Setup regenerates it when a help block is newer, so it cannot drift, and a test asserts that it has a section for every function in the package.

Distributing by zip

Unpack anywhere and run setup. Two points are worth knowing.

  • A zip made from a working tree carries one platform's binary. That is harmless: the extension differs per platform, so a Linux MATLAB simply does not see a .mexw64 and setup compiles a fresh one. On the same platform the timestamp check applies as usual.
  • Prefer a zip made from a clean tree. Everything in .gitignore is exactly what a release archive should not contain, which is convenient: if you build the archive from git archive you get the right contents for free.
$ git archive --format=zip --prefix=referenceSystem/ -o referenceSystem_v2.1.zip HEAD

Making the documentation reachable

Setup does this for you; this section is here for when it reports that it could not. Three files must line up, and any one of them missing is otherwise silent:

FileWhereJob
info.xmlthe distribution folder, on the path Tells MATLAB this folder documents a toolbox, and names the help folder in <help_location>.
helptoc.xmlinside that help folder The Contents tree shown in the Supplemental Software browser.
helpsearch-vN/likewise The search index. Built by referenceSystem.buildDocumentation; without it the pages still open, they just are not found by the search box.

setupReferenceSystem(Verbose=true) reports which of the three is absent, because the three have three different repairs. After a manual change, rehash toolboxcache makes MATLAB notice.

Custom documentation does not display in MATLAB Online. The pages are plain HTML and open in any browser directly from the doc folder.

Removing it

>> referenceSystem.teardownReferenceSystem

This releases the MEX gateway and reports anything else still holding the folder, so that it can be deleted on Windows too. Then remove the folder and, if you saved the path, remove the entry.

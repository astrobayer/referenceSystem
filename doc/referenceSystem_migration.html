Migration from v1

Ordered by what actually bites, most frequent first.

1. Every call site fails immediately — and that is deliberate

Every function is now inside the referenceSystem namespace and every name is camelCase, so every v1 call fails at once as an undefined function. Nothing silently returns a different answer. This is the loudest possible migration and it was chosen over compatibility shims for exactly that reason: a shim would let a v1 script run to completion against v2 semantics.

Find your call sites first:

% every unqualified call to a v1 name
grep -rnE '\b(dcm_?ecef2eci|dcm_?eci2rsw|polarMotionMatrix|ecef2geod|geod2ecef|geod2utm|utm2geod|helmert7|molodensky|itrf_convert|eop_prepare|convertTimeSystem|epochCreate|epochToNumeric|heightConvert)\b' .

% the v1 two-output rotation call, which no longer exists in that form
grep -rnE '\[\s*R\s*,\s*status\s*\]' .

2. R is 3x3xN pages, not Nx9

v1 returned rotation matrices flattened to N-by-9 and every example carried a reshape. v2 returns 3-by-3-by-N pages, which is what pagemtimes and pagetranspose consume directly.

% v1
Rk = reshape(R(k, :), 3, 3)';     % and the transpose was easy to forget

% v2
Rk = R(:, :, k);
rGcrs = pagemtimes(R, rItrs);     % or referenceSystem.applyRotation(R, rItrs)

3. Tidal corrections now default to ON — results differ at ~15 mm

v1 had ApplyTidalCorrections default false. v2 defaults it true, because sub-daily ocean tide and libration reach about 0.5 mas in polar motion and 50 µs in UT1, which is roughly 15 mm at the surface — not optional for GRACE-class work.

% to reproduce a v1 number exactly
R = referenceSystem.rotationItrsToGcrs(epoch, 'Eop', eop, ...
        'ApplyTidalCorrections', false);

Do this only to reproduce an old result, never for new work.

4. The status output is gone entirely

The signature is now [R, Rdot, Rddot, info]. The second output is Rdot, not status. No function anywhere in the toolbox returns a numeric status: SOFA warning conditions surface as MATLAB warnings and SOFA error conditions as MATLAB errors.

% v1
[R, status] = dcm_ecef2eci(...);
if status ~= 0, warning('...'); end

% v2 - delete the status logic entirely
R = referenceSystem.rotationItrsToGcrs(epoch, 'Eop', eop);

info is a diagnostics struct reporting the execution path and the derivative method. It is not a status code: the function still errors rather than signalling.

Every epoch from 2029 onward raises a dubious-year warning on the bundled SOFA leap-second table, which ends at 2017-01-01. Exactly one warning is raised per call regardless of how many epochs you pass, and it names the function you called rather than an internal one.

5. Name mapping

Three naming decisions drive the whole table.

  • Frames use the rigorous IERS names: ITRS and GCRS, not ECEF and ECI. The engineering shorthand survives in rotationEcefToEnu and rotationEcefToNed, where the local-level context makes it unambiguous, and those two functions state the rigorous frame in their METHOD block. lookfor ecef finds them.
  • L4 is named by representation, not by frame: the function converts a Cartesian triple to a geodetic one, and which frame that triple lives in is the caller's business.
  • The epoch constructors are split by source format, and the outbound direction is the single epochTo(epoch, format). This deletes the 'Format' string argument that made the v1 mistake possible.

6. Things that are now stricter, and why

ChangeReason
The default ellipsoid is GRS80, not WGS84. GRS80 is the ITRS ellipsoid of IERS Conventions Table 1.2. The polar radii differ by 1.05e-4 m, which is above this toolbox's own target, so it is asserted in a test rather than mentioned.
Polar motion and CIP offsets are in radians. Units are converted once, at read time. Nothing downstream sees arcseconds.
geoidUndulation errors outside its grid instead of returning NaN. A query outside a regional grid is a mistake in the data, not undefined geometry.
interpolateEop refuses a regularization-tagged correction without 'Regularize', true. Double-correcting the zonal tides is invisible and costs millimetres.
addSeconds and secondsBetween refuse a UTC or GLONASS interval that crosses a leap second. The wrong answer is made unreachable rather than documented.
convertCoordinates refuses "GCRS". That leg needs EOP; nothing else in the graph does. The error names the function to call instead.

referenceSystem — Getting Started

Time systems, Earth orientation and coordinate transformations for satellite geodesy, built on the IERS Conventions (2010) and the unmodified IAU SOFA library. It consolidates three earlier toolboxes (ecef2eci, geodesyToolbox, convertTimeSystem) into one package with a single set of conventions.

Installation

>> cd <wherever you unpacked or cloned it>/referenceSystem
>> setupReferenceSystem

That is all of it. setupReferenceSystem is the installer as well as the path setter: it compiles the MEX gateway, builds the documentation, saves the path and downloads the external data — each step only when it is missing or out of date, and nothing at all when everything is current. A few minutes and about 700 MB on a fresh copy, milliseconds afterwards, so it is safe in startup.m. Pass Fetch="none" for an offline install, or KernelSet="minimal" to leave out the 650 MB small-body kernel.

It is also the only unqualified name the toolbox installs, and the one place permitted to print. It prints by default, and this is what it says:

>> setupReferenceSystem
referenceSystem 2.1.204 is ready.
  root    : /home/you/referenceSystem
  path    : added for this session, saved permanently
  build   : mex built (the gateway is not compiled on this machine),
            reference written, search built
  doc     : registered, /home/you/referenceSystem/doc
  leapsec : last leap second 2017-01-01 (TAI-UTC = 37 s), valid through 2028-12-31
  fetched : 2 EOP file(s), 7 kernel(s), 0 failure(s)

Then, once:

>> referenceSystem.runTestSuite    % writes referenceSystem_testReport.txt

Zip and git installation, what is and is not a build artefact, and what to do when the Help browser cannot find the pages are all covered in Installation and Distribution.

The namespace — read this once

Add the parent folder to the path. Never add +referenceSystem itself. A folder whose name begins with + is a namespace folder, and it is never on the MATLAB path — that is what makes it a namespace. Adding it makes every function visible both qualified and unqualified, which is precisely the collision hazard the namespace exists to prevent. setupReferenceSystem removes it if it finds it there.

Every function is called qualified:

epoch = referenceSystem.mjdToEpoch(60000.5, "UTC");
R     = referenceSystem.rotationItrsToGcrs(epoch, 'Eop', eop);

If unqualified names are preferred, import the namespace in the function that needs them, never at the top of a script that also calls other toolboxes:

import referenceSystem.*
epoch = mjdToEpoch(60000.5, "UTC");

An imported name takes precedence over the path, so import referenceSystem.* shadows any same-named function you have. Two names in this toolbox were renamed for exactly that reason: leapSecondTable (base MATLAB ships leapseconds) and ellipsoidParameters (Mapping Toolbox ships referenceEllipsoid).

The two data types you need

The epoch. A plain struct with a two-part time tag, because a decimal MJD holds only about 5 µs at MJD 60000 — not enough for GRACE ranging.

epoch.day    Nx1 double   integer day number at 0h in the given scale
epoch.sec    Nx1 double   seconds since 0h, [0, 86400) or [0, 86401) across a leap second
epoch.scale  1x1 string   TAI TT TDB TCG TCB UTC UT1 GPS GST BDT GLONASS
epoch.source 1x1 string   provenance, free text

Build one with the constructor that matches your source (mjdToEpoch, daySecondToEpoch, datetimeToEpoch, gpsWeekToEpoch, j2000SecondsToEpoch) and leave with the single epochTo(epoch, format).

The attitude convention. A struct carried with a rotation object rather than ten separate flags, because every wrong combination of sequence, sense, quaternion order and product still yields an orthogonal, unit-determinant matrix that round-trips through its own inverse. There is no runtime symptom; the only defence is that the convention travels with the data and functions consuming two objects compare them.

c = referenceSystem.attitudeConvention();             % geodetic default
c = referenceSystem.attitudeConvention("aerospace");  % NED, scalar-last, Shuster

Workflows

ITRS to GCRS for an arc — the hot path

eop   = referenceSystem.readEop("eopc04_20.1962-now.txt");
utc   = referenceSystem.daySecondToEpoch([day, secondOfDay], "UTC");
[R, Rdot] = referenceSystem.rotationItrsToGcrs(utc, 'Eop', eop);
[rGcrs, vGcrs] = referenceSystem.applyRotation(R, Rdot, rItrs, vItrs);

R is 3x3xN pages, not Nx9. The inverse is the transpose: use invertRotation, or applyRotation(..., 'Inverse', true), which passes the transpose straight to pagemtimes at no cost. There is no direction option anywhere in the toolbox.

Sub-daily tidal corrections default to ON (about 15 mm at the surface). This differs from v1.

Changing terrestrial realization

xItrf2020 = referenceSystem.convertItrf(xItrf2008, "ITRF2008", "ITRF2020", 2015.5);

Ground station visibility

enu = referenceSystem.cartesianToEnu(satelliteItrs, stationGeodetic, 'AngleUnit', "deg");
ael = referenceSystem.enuToAzimuthElevation(enu);     % azimuth CLOCKWISE FROM NORTH
visible = ael(:, 2) > deg2rad(10);

One call across the geometry graph

geodetic = referenceSystem.convertCoordinates(xItrs, "ITRS", "GEODETIC");

convertCoordinates routes across the L3 and L4 transformations. It deliberately does not include ITRS ↔ GCRS: that leg needs Earth orientation data, everything else needs none, and mixing them would hide the requirement. Asking for "GCRS" raises referenceSystem:convertCoordinates:useRotationFunction and names the function to call.

Conventions that will bite you if you skip them

RuleWhy
SI units everywhere inside. Polar motion and CIP offsets are in radians, never arcseconds. IERS files publish arcseconds; readEop converts once, at read time. Passing arcseconds to rotationTirsToItrs gives a matrix that is still orthogonal and wrong by five orders.
L2 takes 3xN (one column per epoch); L3 and L4 take Nx3 (one point per row). A 3x3 array is therefore three points in L4 and never one transposed triple. Resolved by the documented rule, never by inspection.
No status codes. Nothing returns a numeric status. SOFA warnings become MATLAB warnings and SOFA errors become MATLAB errors. info structs are diagnostics, not signals.
The default ellipsoid is GRS80, not WGS84. GRS80 is the ITRS ellipsoid of IERS Conventions Table 1.2. The polar radii differ by 1.05e-4 m.
Epochs from 2029 onward warn. The bundled SOFA leap-second table ends at 2017-01-01 and SOFA reports a dubious year beyond its horizon. Supply a current table through leapSecondTable before operational use.
